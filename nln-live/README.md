# NLN Customer-Ready Website Candidate

Separate from the existing `nln-preview/` concept and the older NLN dispatch server.

## Implemented
- Responsive, mobile-first business website and 5 dedicated SEO service pages
- Accurate $199 / $399 / $699 / $999 / $1,999 / $3,995.50 package pricing
- Separate optional $39/year .com domain registration offer
- Portfolio referencing the owner's Citywide website, NLS store project, and Find Me a Locksmith marketplace preview
- Accessible AJAX contact form, privacy notice, terms, no payment collection
- Server-side validation, same-origin checks, basic spam and rate limiting
- Private admin inquiry inbox with status updates and CSV export
- Isolated `nln_business_inquiries` table on the pre-existing paid NLN Postgres instance (no writes to legacy `leads` table)
- Server-controlled `X-Robots-Tag: noindex,nofollow` on all pages until launch conditions pass
- Dynamic canonical URLs, Google verification meta tag, sitemap.xml and robots.txt

## Production requirements

The Blueprint at `nln-live/render.yaml` attaches the EXISTING Render Postgres database named `nln-database`. It creates a new **free web service** but does not modify the legacy routing server. Plan and review it before approval. The new web service needs successful database health and form-submission tests.

### Important free-web-service caveat
Render free web instances spin down after inactivity. Their `robots.txt` endpoint can return a temporary disallow-all during spin-down. Move the marketing site to reliable always-on hosting before enabling public search indexing. The existing paid NLN Postgres DB is retained.

### Switches
- `SEARCH_INDEXING_ENABLED=false` by default: keeps site out of search results.
- `SITE_URL`: set to the verified owned domain, e.g. `https://<your-domain>`, **after** purchase/ownership confirmation and DNS linking.
- `INTAKE_OPEN=true`: enable only when the database connection is healthy.
- `ADMIN_KEY`: generated by Render and stored in service environment; do not commit it or email it.
- `GSC_VERIFICATION_TOKEN`: fill using the exact meta content generated by Google Search Console.
- `RESEND_API_KEY`, `LEAD_FROM_EMAIL`, `LEAD_NOTIFY_EMAIL`: optional email notification via verified account; not needed for inbox.
- `PGSSL=true`: optional for environments requiring SSL.

### Search Console
1. Configure the owned domain through the Render dashboard.
2. Verify `https://domain/` works with TLS, real inquiry form and inbox, privacy notice, mobile layout.
3. Add the Google-provided verification value to `GSC_VERIFICATION_TOKEN` or use DNS TXT verification with the registrar.
4. After indexing readiness sign-off, set `SITE_URL` and `SEARCH_INDEXING_ENABLED=true`.
5. Check `/robots.txt`, `/sitemap.xml`, and live response headers.
6. Submit sitemap in Search Console. Google does not guarantee indexing or ranking.

### Do not claim
- Payment processing, subscription billing, call answering, Google Ads discounts or automatic lead delivery beyond this database-backed form.
- That NLN is a Google Partner, endorsed by Google, or eligible for a Google Business Profile as an online-only business.
- That connected projects are unrelated paid customer engagements or evidence of ranking/conversion results.

### Security tasks before launch
- Review access and rotate any known/legacy admin credentials in the separate old NLN routing app.
- Add proper monitoring/backups, agreed privacy/terms review, abuse throttling by shared datastore and confirmed notification recipient.
- Add email notifications using an authenticated provider (optional) and test delivery.
